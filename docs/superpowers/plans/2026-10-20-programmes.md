# First Key: difficulté de programmation croissante — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Faire évoluer la difficulté de programmation: programmes multi-lignes (variables, boucles imbriquées, fonctions, conditions), programmes généraux testés sur 3 mondes et budgets de lignes, aux niveaux 73-114.

**Architecture:** `assets/js/maze/lang.js` gagne un mode « programme » (AST étendu) et `world.js` un interpréteur étendu; un nouveau module pur `assets/js/maze/levels.js` décrit chaque niveau (`levelSpec`) et fournit les familles, programmes de référence, budgets et mondes des niveaux 73-114; `ui-maze.js` ajoute l'éditeur multi-lignes.

**Tech Stack:** JS ES modules, aucune dépendance. **Spec:** `docs/superpowers/specs/2026-10-20-programmes-design.md` (suite de `2026-10-20-labyrinthes-design.md`).

## Global Constraints
- Site statique, modules ES, pas de build, aucune dépendance; `npm test` reste vert; les niveaux 1-72 et le terminal ligne par ligne ne changent pas de comportement (tests existants verts).
- Jamais `eval` / `new Function` / `import()` sur du texte tapé; analyseur écrit à la main, sans regex à retour arrière catastrophique.
- Déterminisme: un niveau est identique à chaque appel (PRNG à graine, pas de `Math.random`).
- Chaque niveau 73-114 a un **programme de référence** (Python et JavaScript) qui est exécuté par les tests, atteint l'étoile (dans les 3 mondes au palier 7) et dont le nombre de lignes + 1 est le budget.
- Garde-fous d'exécution de la spec (500 actions, 5 000 instructions, profondeur 4, 40 lignes, boucles ≤ 99, |valeur| ≤ 999).
- Textes via `textContent`; messages d'erreur en français bienveillant avec numéro de ligne.
- La couche `fx` reste inerte; contenu dans les 62 % du haut; événements `firstkey:*` inchangés (`display: '⭐'`, `kind: 'letter'`).

## Review Focus
1. Langage: entrées hostiles (récursion directe/indirecte, `while` sans action, imbrication > 3, indentation mixte, tabulations, très longues lignes, 41 lignes, valeurs énormes, noms réservés `constructor`/`__proto__`, redéfinition de `forward`, Unicode) → erreur propre ou résultat borné, jamais exception ni gel.
2. Chaque niveau 73-114: déterministe, distinct, soluble, référence exécutée dans les deux langages, budget = lignes de référence + 1 atteignable, mondes du palier 7 réellement différents et tous résolus par la référence.
3. Équivalence Python / JavaScript: mêmes programmes équivalents → mêmes événements.
4. UI: texte tapé jamais perdu (erreur, quitter, relancer), focus et Tab, Échap, Ctrl+Entrée, annulation de l'animation en quittant, état relu après événements, victoire refusée au-delà du budget avec message clair, 3 mondes testés dans l'ordre.
5. Anciennes sauvegardes: niveaux 1-72 inchangés, un joueur au niveau 80 tombe sur un niveau de palier 5 valide.

### Task 1: Langage de programme et interpréteur (pur)
**Files:** Modify `assets/js/maze/lang.js`, `assets/js/maze/world.js`; Test `tests/maze-lang.test.js`, `tests/maze-world.test.js`.
**Interfaces — Produces:**
- `parseProgram(src: string, lang: 'py'|'js'): { ok: true, program: Program, lines: number } | { ok: false, error: { code, message, hint?, line?: number } }` avec `Program = { funcs: Record<string, { param: string|null, body: Stmt[] }>, body: Stmt[] }`. `Stmt` étend celui de la spec 5: `{ t:'call', name:'forward'|'left'|'right', n: Expr }`, `{ t:'loop', n: Expr, v: string, body }`, `{ t:'if', cond: Cond, body, else?: Stmt[] }`, `{ t:'while', cond: Cond, body }`, `{ t:'set', name: string, op: '='|'+='|'-=', e: Expr }`, `{ t:'callfn', name: string, arg?: Expr }`; `Expr = { k:'num', v } | { k:'var', name } | { k:'bin', op:'+'|'-'|'*', a, b }`; `Cond = { k:'sense', name:'wall'|'goal', neg: boolean } | { k:'cmp', op:'<'|'>'|'==', a: Expr, b: Expr }` (négation `not`/`!` devant un capteur ou une comparaison entre parenthèses non supportées: `not wall()` / `!wall()` seulement). Le `parse` existant (une ligne) **reste** et garde ses AST actuels; `lines` = nombre de lignes non vides du programme.
- `world.js`: `executeProgram(program, world): { world, events: Event[], error?: { code: 'limit'|'steps'|'depth'|'value'|'undefined', line?: number } }` (mêmes `Event` que `execute`: move/turn/bump/goal; `bump` arrête tout le programme, `goal` aussi; 500 actions max, 5 000 instructions max, profondeur d'appel ≤ 4, valeurs bornées, variable non définie → erreur gentille) pur (n'altère pas ses entrées).
Messages d'erreur (codes): `indent`, `tab`, `recursion`, `too_deep` (imbrication > 3), `too_many_lines` (> 40), `undefined_name`, `duplicate_fn`, `reserved`, `block_missing`, `else_alone`, `bad_expr`, plus ceux de la spec 5. Python: indentation par espaces cohérente (2 ou 4), tabulations refusées; JavaScript: accolades.
- [ ] **Step 1 tests:** programmes valides dans les deux langages donnant le même AST (exemples: double boucle avec variable; fonction `carre()` appelée 4 fois; fonction à paramètre; `if wall(): … else: …`; `while not wall(): forward()`; `n = 2` puis `n += 1` puis `forward(n)`; variable de boucle `i` dans `forward(i + 1)`); exécution: variables, boucles imbriquées, appels, `else`, `while` sans action (limite d'instructions, pas de gel), récursion refusée (directe et indirecte, à l'analyse), profondeur, valeurs bornées, bump/goal arrêtent tout le programme; entrées hostiles (liste du Review Focus 1) + fuzz de 3 000 chaînes à graine: jamais d'exception; temps borné (1 s max) sur 40 lignes pathologiques; équivalence py/js sur 10 programmes jumeaux (mêmes événements); numéros de ligne dans les erreurs.
- [ ] **Step 2:** échec; **Step 3:** implémenter; **Step 4:** `npm test` vert (les tests des tâches précédentes aussi); **Step 5: Commit** `feat: programmes multi-lignes, variables, fonctions et conditions`.

### Task 2: Curriculum en tours, niveaux 1-114, références, budgets et mondes (pur)
**Files:** Create `assets/js/maze/levels.js`, `assets/js/maze/curriculum.js`; Modify `assets/js/maze/gen.js` (réécriture: segments étiquetés; `tierOf` supprimé ou remplacé; `solve`/`solutionPath`/`DIRS` conservés), `assets/js/progress.js` (`answersPerLevel(age, 'maze') = 3`); Test `tests/maze-levels.test.js`, `tests/maze-curriculum.test.js`, adapter `tests/maze-gen.test.js`, `tests/maze-world.test.js`, `tests/progress.test.js`.
**Interfaces — Produces:**
- `curriculum.js`: `CURRICULUM: { level: number, name: string, focus: string, skills: string[], isNew: boolean }[]` (114 lignes, échelle de la spec « Tours »: les étiquettes de segments sont des chaînes comme `straight`, `turnR`, `turnL`, `L`, `Z`, `U`, `long`, `square`, `loop`, `stairs`, `spiral`, `zigzag`, `nested`, `vars`, `fn`, `general`…); `skillIntro(level): string|null` (nom de la notion nouvelle si `isNew`).
- `levels.js`: `levelSpec(level: number, exercise: 0|1|2): { level, exercise, mode: 'repl'|'program', tags: string[], worlds: Maze[] /* 1 monde, 3 au palier 7 */, budget: { py: number, js: number } | null, reference: { py: string, js: string } | null, hint: string }`; `repl` pour 1-72, `program` pour 73-114; `Maze = { w, h, walls, start:{x,y,dir}, goal:{x,y}, par, tags: string[] }`.
- `gen.js`: `makeMaze(level, exercise = 0)` = `levelSpec(level, exercise).worlds[0]`; assemblage à partir de segments étiquetés; déterministe (PRNG à graine dérivée de `(level, exercise)`), toujours soluble, `maze.tags` = étiquettes des segments utilisés, grille ≤ 11×11, difficulté croissante avec l'exercice (plus de segments, branches plus longues).
Règles de tour (testées): pour chaque niveau L et chaque exercice e: `tags` contient `focus(L)`; pour e ≥ 1 (et L ≥ 2) il contient `focus(L-1)`; pour e = 2 il contient en plus au moins deux autres étiquettes déjà apprises (quand elles existent). Les 3 exercices d'un tour sont **deux à deux différents**; tous les labyrinthes de 1..114 × 3 sont distincts entre eux (ou presque: au plus quelques doublons tolérés seulement s'ils sont inévitables aux tout premiers niveaux, à justifier dans le rapport). Les niveaux 1-72 doivent pouvoir se résoudre avec les commandes de la spec 5 (`forward`, virages, `forward(n)`, boucle une ligne) et **demander** la notion du tour (ex.: au tour 41 le chemin est un carré/rectangle de motif répété qu'une boucle écrit en une ligne; sans boucle il faut > 8 commandes). Niveaux 73-114: familles (serpent à boucle imbriquée, spirale à variable, carrés/escaliers à compteur; motifs répétés pour une fonction avec/sans paramètre; mondes à longueurs inconnues pour `while`/`if`/`else`), chacun avec `reference` (py + js) et `budget = lignes de la référence + 1` par langage, 3 mondes distincts au palier 7 où la référence atteint l'étoile dans chacun mais où un programme écrit pour un seul monde échoue sur un autre.
- [ ] **Step 1 tests:** curriculum (114 lignes, `isNew` aux niveaux 1, 7, 13, 19, 25, 33, 41, 53, 63, 73, 87, 101, focus non vide, notions cumulées croissantes); pour tout (level, exercise): solubilité (`solve`), déterminisme, tags conformes aux règles de tour, difficulté non décroissante avec `exercise` (par `par` ou nombre de segments), tailles ≤ 11, 3 exercices distincts; niveaux 1-12 couloirs droits; pour 73..114 × exercices × 2 langages: `parseProgram(reference)` ok (Task 1), `lines + 1 === budget`, `executeProgram` atteint l'étoile dans chaque monde; palier 7: mondes distincts 2 à 2 et généralité (un programme `forward()` répété écrit pour un monde échoue sur un autre); notion « demandée »: aux tours de boucle (41-72) la solution la plus courte sans boucle est nettement plus longue (≥ 2× le programme avec boucle) — tester avec les `reference` de ces niveaux si fournies (`reference` aussi pour 41-72 en `repl`); `answersPerLevel(8, 'maze') === 3`.
- [ ] **Step 2:** échec; **Step 3:** implémenter; **Step 4:** `npm test` vert (adapter les tests de la spec 5 qui supposaient 1 exercice par niveau ou les anciens paliers); **Step 5: Commit** `feat: curriculum en tours de 3 exercices, niveaux 1-114`.

### Task 3: Éditeur de programme dans le jeu
**Files:** Modify `assets/js/ui-maze.js`, `assets/css/style.css`, `assets/js/ui-home.js` (aucun changement si inutile); pas de test automatique du DOM.
**Interfaces — Consumes:** `levelSpec(level, exercise)` (l'exercice courant est `state.progress.maze.correct` pour le niveau en cours, ou un compteur local 0..2 pour un niveau rejoué), `CURRICULUM`, `skillIntro`, `parseProgram`, `executeProgram`, `commandNames`, existants de la spec 5. **Produces:** pour `levelSpec(level, exercise).mode === 'program'`, `startMaze` affiche l'éditeur (voir spec « Interface »), sinon le terminal actuel.
Comportement détaillé: voir la spec. Bandeau « Tour N · Exercice k/3 » avec le nom du tour (`CURRICULUM[level].name`), encadré « Nouveau: … » quand `skillIntro(level)` n'est pas nul et que c'est l'exercice 1, barre de niveau 1/3 · 2/3 · 3/3 (utiliser `answersPerLevel(age, 'maze')`), l'exercice suivant se charge avec `levelSpec(level, nextExercise)` et `ui-maze.js` utilise `levelSpec` partout (y compris les tours 1-72 en terminal). En plus: le texte de l'éditeur est conservé tant qu'on reste sur le niveau (échec, erreur, relance) et vidé à la victoire; budget affiché pour le langage actif (`budget[lang]`); si le héros atteint l'étoile (tous les mondes au palier 7) mais `lines > budget`, aucune victoire: message « Ça marche! Peux-tu l'écrire en N lignes? » et le héros revient au départ; en cas de victoire la voie commune (`recordCorrect`, événements, relecture de `getState()`, niveau suivant) est identique à la spec 5; vignettes des mondes au palier 7 (✓/✗/◌, monde en cours surligné); Échap sort de l'éditeur (le Tab suivant quitte le champ), Tab insère l'indentation (4 espaces en Python, 2 en JS), Entrée garde l'indentation de la ligne précédente (+ un cran après `:` ou `{`), Ctrl/Cmd+Entrée = Lancer; `prefers-reduced-motion`: déplacements instantanés; nettoyage complet en quittant (jeton d'annulation vérifié à chaque continuation asynchrone).
- [ ] **Step 1:** implémenter. **Step 2:** `npm test` vert. **Step 3: vérification Chrome** (`python3 -m http.server 8000`, rechargement forcé, sauvegarde/restauration de `localStorage`): sauter aux niveaux 73, 80, 87, 95, 101, 110 (réglages parent ou graine de `progress.maze.level`), résoudre avec la **référence** (non affichée: la lire via un petit script de console `import('/assets/js/maze/levels.js')`) en Python puis en JavaScript; tester une erreur de syntaxe (numéro de ligne), un programme trop long (message de budget), un programme qui n'atteint pas l'étoile, une boucle infinie `while not goal(): turn_left()`, le palier 7 (3 mondes, vignettes), Tab/Échap/Ctrl+Entrée, retour pendant une animation (aucune erreur), 360 px sans défilement horizontal, récompenses de la spec 2 intactes, niveaux 1-72 inchangés. **Step 4: Commit** `feat: éditeur de programme, budgets et mondes multiples`.
