# First Key: bloc Calcul — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Rendre le bloc Calcul jouable: QCM (niveaux 1-57) puis réponse tapée (58-114), 4 opérations.

**Architecture:** Un module pur `assets/js/math.js` génère les questions (testé avec `node --test`). `questions.js` route le bloc `math` vers lui. `ui-game.js` gère un nouveau type de question `choice` (boutons) et l'affichage de l'énoncé avec réponse tapée.

**Tech Stack:** JS ES modules, aucune dépendance. **Spec:** `docs/superpowers/specs/2026-10-19-calcul-design.md`.

## Global Constraints
- Site statique, modules ES, pas de build, aucune dépendance; `npm test` (`node --test`) reste vert.
- Textes via `textContent`; pas de `innerHTML` avec des données.
- Aucune question impossible: pas de résultat négatif, division exacte, jamais ÷0, propositions QCM toutes différentes, entières, ≥ 0.
- Mauvaise réponse = son raté + réessai (pas d'animation, pas de pénalité). La couche `fx` (spec 2) reste inerte; les événements `firstkey:correct`/`firstkey:wrong`/`firstkey:levelup` gardent leur forme (`kind: 'letter'` pour le calcul).
- Bords: `e.repeat` ignoré, touches AZERTY chiffres via `e.code`, pas de fuite d'écouteurs à la sortie du jeu.

## Review Focus
1. Tous les niveaux 1 à 114 génèrent une question valide (résultat juste, non négatif, division exacte, QCM sans doublon, bonne réponse présente) sur plusieurs milliers de tirages.
2. Le QCM n'est jamais bloqué: clic, toucher, touches 1-4 et pavé numérique; un mauvais choix ne fait pas avancer; la bonne réponse enregistre exactement un point (pas de double comptage par touche + clic).
3. Réponse tapée à plusieurs chiffres: un chiffre faux ne fait pas reculer; énoncé et chiffres tapés lisibles aux grandes valeurs (ex. `998 + 999 = 1997`).
4. Quitter le jeu en plein QCM ne laisse ni écouteur ni bouton actif.
5. Sauvegarde et rewards inchangés; saut de niveau parent sur `math` fonctionne.

### Task 1: Générateur de questions de calcul (module pur)
**Files:** Create `assets/js/math.js`; Test `tests/math.test.js`.
**Interfaces — Produces:** `mathSpec(level: number): { op: 'add'|'sub'|'mul'|'div'|'mix', mode: 'choice'|'typed', choices: 3|4 }` (`mode` = `'choice'` si `level ≤ 57`, `choices` = 3 si `level ≤ 20` sinon 4); `makeMathQuestion(level: number, rng = Math.random): { prompt: string, answer: number, mode: 'choice'|'typed', choices?: number[], answerIndex?: number, accepts: string[] }` où `prompt` est l'énoncé sans résultat (`'7 × 8'`, opérateurs `+ − × ÷`), `accepts = [String(answer)]`, `choices` (mode choice) contient `answer` à `answerIndex`.
Règles des bornes (spec « Mes choix »): add niveaux 1-24 somme max 5→100 (linéaire); sub 25-44 `a` max 10→100, `a ≥ b`; mul 45-74 (facteurs 1..10, bornes croissantes: ×5 max au 45, ×10 au 74, tables 11 et 12 seulement en mix); div 75-94 `a ÷ b` exacte avec `b ≥ 1` issue des tables; mix 95-114 les 4 opérations, add jusqu'à 1000 au 114. Distracteurs: proches du résultat (±1, ±2, ±10, résultat d'une autre opération sur les mêmes opérandes), uniques, entiers, ≥ 0, différents de `answer`; mélangés avec `rng` (position de la bonne réponse aléatoire).
- [ ] **Step 1 tests** (`tests/math.test.js`): `mathSpec` aux niveaux 1, 20, 21, 57, 58, 114; pour les 114 niveaux × 300 tirages avec un `rng` pseudo-aléatoire déterministe: le résultat de `prompt` recalculé égale `answer`, `answer ≥ 0`, entier, division exacte et diviseur ≥ 1, QCM: `choices.length` = `mathSpec(level).choices`, tous uniques entiers ≥ 0, `choices[answerIndex] === answer`; typed: pas de `choices`; la bonne réponse apparaît à toutes les positions sur un grand nombre de tirages; les opérateurs attendus par bande de niveaux (level 1 → `+` seulement, 30 → `-`, 50 → `×`, 80 → `÷`, 100 → tous présents sur 300 tirages); bornes (niveau 1: opérandes ≤ 5; niveau 114: add ≤ 1000).
- [ ] **Step 2:** `npm test` → échec. **Step 3:** implémenter. **Step 4:** `npm test` → vert. **Step 5: Commit** `feat: générateur de questions de calcul`.

### Task 2: Brancher le calcul dans les questions et le jeu
**Files:** Modify `assets/js/blocks.js` (math `playable: true`), `assets/js/questions.js`, `assets/js/ui-game.js`, `assets/css/style.css`; Test `tests/questions.test.js`.
**Interfaces — Consumes:** `makeMathQuestion` (Task 1). **Produces:** `makeQuestion('math', level, settings, rng)` renvoie `{ kind: 'choice', display: prompt, hint: '', choices: string[], answerIndex: number }` en mode QCM, ou `{ kind: 'typed', display: prompt, accepts: [answer], math: true }` en mode tapé (les questions lettres/mots restent inchangées, `kind` absent = typé comme avant). `answerKind('math', …)` reste `'letter'`.
Comportement `ui-game.js`:
- QCM: sous l'énoncé (`.display`, énoncé seul, ex. `7 × 3`), 3 ou 4 gros boutons colorés (`.choice`, étiquette de position 1-4 visible, nombre en grand), `button` réels; clic/toucher ou touche `1`-`N` (chiffre de la rangée du haut et pavé, via `e.key` puis repli `e.code`) choisit; bon choix → même chemin qu'une bonne réponse typée (son `correctAnswer`, `recordCorrect`, événements, question suivante); mauvais choix → événement `firstkey:wrong`, son `wrongAnswer`, le bouton se grise et se désactive, l'enfant réessaie. Une seule validation par question (verrou pendant le passage à la suivante, pas de double comptage clic + touche). Le clic ne doit pas lancer d'écouteur clavier en plus.
- Tapé: afficher l'énoncé suivi de ` = ` puis les chiffres tapés (`.typed`, en vert) et des `?` pour le reste; même gestion `createTyper`, AZERTY et `e.repeat` que l'existant; taille de police réduite pour les longs énoncés (`998 + 999 = 1997`) sans débordement horizontal.
- `rect` de `firstkey:correct` = rectangle de l'élément `.display`; `display` = énoncé.
- À la sortie (`exit`): retirer les écouteurs et les boutons (le DOM est remplacé par l'accueil).
