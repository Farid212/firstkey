# First Key: Programmation en jeu (labyrinthes) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Ajouter le bloc « Programmation »: guider une créature dans des labyrinthes en tapant des commandes Python/JavaScript dans un terminal.

**Architecture:** Trois modules purs testés sous Node (`assets/js/maze/gen.js` génération + résolution, `lang.js` analyseur, `world.js` exécution produisant des événements) et un module DOM `assets/js/ui-maze.js` qui rejoue les événements en animation. Le reste (blocs, progression, réglages, accueil, récompenses) est branché sur l'existant.

**Tech Stack:** JS ES modules, SVG + CSS, aucune dépendance. **Spec:** `docs/superpowers/specs/2026-10-20-labyrinthes-design.md`.

## Global Constraints
- Site statique, modules ES, pas de build, aucune dépendance; `npm test` (`node --test`) reste vert.
- Aucun `eval`/`new Function`/`import()` sur du texte tapé. Textes affichés via `textContent`.
- Labyrinthes déterministes par niveau (PRNG à graine, pas de `Math.random`) et toujours solvables.
- Aucune boucle infinie: plafond de 300 actions par ligne, 99 répétitions par boucle.
- Rien ne bloque la frappe: le terminal garde le focus; la couche `fx` (récompenses) reste inerte; contenu dans les 62 % du haut de l'écran.
- Événements `firstkey:*` gardent leur forme (`kind: 'letter'`); `e.repeat` n'est pas un sujet ici (vrai `<input>`).
- Erreurs en français, bienveillantes.
- Pas de régression sur lettres, mots, calcul, quiz JS/Python, récompenses, collection.

## Review Focus
1. Le langage: toute entrée (aléatoire, très longue, caractères Unicode, `forward(99999)`, `for i in range(99): for…`, parenthèses déséquilibrées, `while` infini) renvoie une erreur propre ou un résultat borné, jamais une exception ni un blocage.
2. Chaque niveau 1-114 est solvable par un programme dans la grammaire; le niveau est identique à chaque appel; la progression de taille est monotone.
3. Quitter l'écran (retour, réglages) en pleine animation ne laisse ni minuteur, ni écouteur, ni sortie de terminal fantôme; l'état et les récompenses ne sont pas écrasés (relecture `getState()` après les événements).
4. Terminal accessible: focus, Entrée/Tab/flèches, clavier virtuel, Tab non piégé, lecteur d'écran (annonce des résultats).
5. Anciennes sauvegardes: le bloc `maze` apparaît, `settings.codeLanguage` absent → `'py'`, `answersPerLevel` des autres blocs inchangé.

### Task 1: Générateur et solveur de labyrinthes (pur)
**Files:** Create `assets/js/maze/gen.js`; Test `tests/maze-gen.test.js`.
**Interfaces — Produces:** `DIRS = [{x:0,y:-1},{x:1,y:0},{x:0,y:1},{x:-1,y:0}]` (0 = nord, 1 = est, 2 = sud, 3 = ouest, tourner à droite = +1); `makeMaze(level: number): { w: number, h: number, walls: boolean[][] /* walls[y][x] */, start: { x, y, dir }, goal: { x, y }, par: number, tier: 1|2|3|4|5|6 }` (déterministe: PRNG à graine dérivée de `level`); `tierOf(level): 1..6` selon les paliers de la spec (1-12, 13-30, 31-48, 49-72, 73-94, 95-114); `solve(maze): number` = nombre minimal de commandes unitaires (`forward` d'une case, `turn_left`, `turn_right`) pour atteindre `goal` depuis `start` (BFS sur (x, y, dir)), ou `-1` si impossible. `par = solve(maze)`.
Règles: grille 5×5 au niveau 1 jusqu'à 11×11 au niveau 114 (taille non décroissante); `start` et `goal` sur des cases libres, `goal ≠ start`; palier 1: couloir droit de 2 à 6 cases, `start.dir` face à l'étoile; palier 2: chemins en L/Z (2 à 4 virages); palier 3: couloirs un peu plus longs; palier 4: motifs répétés (escalier/spirale) où une boucle `for` est naturelle; paliers 5-6: chemin principal aléatoire (marche auto-évitante) plus des impasses de plus en plus nombreuses; murs partout ailleurs; bords entourés de murs ou de la limite de grille (sortir de la grille compte comme un mur).
- [ ] **Step 1 tests:** pour 1..114: `solve(makeMaze(l)) === maze.par ≥ 1`; `makeMaze(l)` deux fois → `deepEqual`; départ/arrivée libres et distincts; dimensions bornées 5..11 et non décroissantes avec le niveau; niveaux 1..12: toutes les cases libres forment un seul couloir droit et `start.dir` regarde l'étoile; chaque palier cité apparaît dans `tierOf`; deux niveaux voisins du même palier donnent des labyrinthes différents (au moins 90 % des paires 13..30 sont différentes); `solve` sur un petit labyrinthe écrit à la main (valeur connue) et sur un cas sans solution (`-1`).
- [ ] **Step 2:** `npm test` → échec; **Step 3:** implémenter; **Step 4:** vert; **Step 5: Commit** `feat: générateur de labyrinthes`.

### Task 2: Analyseur de commandes Python/JavaScript (pur)
**Files:** Create `assets/js/maze/lang.js`; Test `tests/maze-lang.test.js`.
**Interfaces — Produces:** `parse(src: string, lang: 'py'|'js'): { ok: true, prog: Stmt[] } | { ok: false, error: { code: string, message: string, hint?: string } }` où `Stmt = { t: 'call', name: 'forward'|'left'|'right', n: number } | { t: 'loop', n: number, body: Stmt[] } | { t: 'if', cond: 'wall'|'goal', neg: boolean, body: Stmt[] } | { t: 'while', cond: 'wall'|'goal', neg: boolean, body: Stmt[] }`; `commandNames(lang): { forward: string, left: string, right: string }` (py: `forward`, `turn_left`, `turn_right`; js: `forward`, `turnLeft`, `turnRight`); `suggest(word: string, lang): string | null` (nom de commande le plus proche, insensible à la casse, distance d'édition ≤ 2).
Grammaire exacte: voir la spec (« Commandes »). Une ligne = liste d'instructions séparées par `;` (Python: le corps d'un `for`/`if`/`while` va après `:` jusqu'à la fin de la ligne et peut contenir des `;`; JavaScript: corps = une instruction ou `{ ... }`). Espaces libres. Pas de boucles imbriquées dans cette version (un `for` dans un corps → erreur claire). `forward` accepte `()` ou `(n)` avec `1 ≤ n ≤ 99`; `range(n)` / `i < n` avec `1 ≤ n ≤ 99`. Les messages en français, courts, sans jargon effrayant (codes: `unknown_command`, `missing_paren`, `bad_number`, `empty`, `syntax`, `nested`, `too_big`). Analyse par jetons et descente récursive, jamais d'`eval`.
- [ ] **Step 1 tests:** toutes les formes valides des deux langages (appels, argument, `;` multiples, `for` avec/sans accolades, `if`/`if not`/`if (!x)`, `while`) → AST attendu exact; entrées invalides: chaîne vide/espaces (`empty`), `forwad()` (`unknown_command` + `hint` contenant `forward`), `Forward()` (hint `forward`), `turn_left` sans parenthèses (`missing_paren`), `forward(0)`, `forward(100)`, `forward(-1)`, `forward(a)` (`bad_number`), boucles imbriquées (`nested`), parenthèses/accolades non fermées, `for i in range(): …`; entrée très longue (10 000 caractères) et caractères Unicode/`eval("1")`/`__import__`/`constructor` → erreur propre, jamais d'exception ni d'exécution; fuzz: 2 000 chaînes pseudo-aléatoires (PRNG à graine) tirées d'un alphabet de jetons et de symboles ne lèvent jamais d'exception; une commande JS dans le mode py (`turnLeft()`) donne `unknown_command` avec hint `turn_left`.
- [ ] **Step 2:** échec; **Step 3:** implémenter; **Step 4:** vert; **Step 5: Commit** `feat: analyseur de commandes du labyrinthe`.

### Task 3: Exécution dans le monde (pur) + intégration du bloc
**Files:** Create `assets/js/maze/world.js`; Modify `assets/js/blocks.js`, `assets/js/progress.js`, `assets/js/store.js`; Test `tests/maze-world.test.js`, `tests/progress.test.js`, `tests/store.test.js`.
**Interfaces — Produces:**
- `world.js`: `createWorld(maze): World = { maze, x, y, dir, done: boolean }`; `execute(prog: Stmt[], world: World): { world: World, events: Event[], error?: { code: 'limit' } }` pur (ne modifie pas l'entrée). `Event = { k: 'move', x, y, dir } | { k: 'turn', dir } | { k: 'bump', x, y, dir } | { k: 'goal', x, y }`. Sémantique: `forward(n)` avance case par case; devant un mur ou hors grille → événement `bump` et la ligne entière s'arrête; arriver sur `goal` → événement `goal`, `done = true` et l'exécution s'arrête; `turn` change `dir` (±1 modulo 4); `wall()` vrai si la case devant est un mur ou hors grille; `goal()` vrai si sur l'étoile; `for` répète `n` fois le corps; `while` répète tant que la condition vaut vrai (négation comprise); plafond de 300 actions (`move`/`turn`) par appel d'`execute`: au-delà, arrêt avec `error: { code: 'limit' }`.
- `blocks.js`: nouveau bloc `{ id: 'maze', label: 'Programmation', playable: true, minAge: 7, mix: false }` placé après `math`; libellés `js` → « Quiz JavaScript », `python` → « Quiz Python ».
- `progress.js`: `answersPerLevel(age, blockId?)` retourne `1` pour `blockId === 'maze'`, sinon la valeur actuelle; `recordCorrect` l'utilise avec le bloc joué; `pickBlock` ignore les blocs `mix: false`.
- `store.js`: `settings.codeLanguage` (`'py'` par défaut, validé dans `['py','js']`); migration: une sauvegarde dont `settings.blocks` contient tous les anciens blocs (`letters, words, math, js, python`) et pas `maze` reçoit `maze` (évite de cacher le nouveau bloc aux anciens joueurs); `progress.maze` créé par défaut comme les autres.
- [ ] **Step 1 tests:** `world`: avancer, tourner (4 virages = retour), bump (état inchangé, ligne arrêtée, événements corrects), goal (done, arrêt), `for`/`if`/`while` avec capteurs, plafond de 300 actions (`while not goal(): turn_left()` ne gèle pas), pureté (entrée non modifiée); tous les niveaux 1-114: le programme « BFS » reconstruit depuis `solve` atteint le but avec `execute` (ajouter dans `gen.js` si utile un `solutionPath(maze): ('f'|'l'|'r')[]`, exporté pour les tests); `progress`: `answersPerLevel(8)` = 25 et `answersPerLevel(8, 'maze')` = 1, `recordCorrect` sur `maze` monte d'un niveau à chaque réussite, `pickBlock` n'en tire jamais `maze`; `store`: défaut `codeLanguage`, valeur invalide → `'py'`, migration des anciennes sauvegardes, `maze` présent dans `progress`; adapter les tests existants impactés (listes de blocs, `BLOCKS`).
- [ ] **Step 2:** échec; **Step 3:** implémenter; **Step 4:** `npm test` vert; **Step 5: Commit** `feat: exécution des commandes et bloc Programmation`.

### Task 4: Interface du jeu de labyrinthe
**Files:** Create `assets/js/ui-maze.js`; Modify `assets/js/main.js`, `assets/js/ui-home.js` (icône du bloc), `assets/js/ui-game.js` seulement pour la barre de progression si besoin (`answersPerLevel(age, blockId)`), `assets/css/style.css`; pas de test automatique pour le DOM.
**Interfaces — Consumes:** `makeMaze`, `parse`, `commandNames`, `suggest`, `createWorld`, `execute`, `getArt`, `CREATURES` (dernière créature débloquée: `CREATURES[state.rewards.unlocked - 1]`), `recordCorrect`, événements `firstkey:*`. **Produces:** `startMaze(root, state, target, handlers)` avec les mêmes `handlers` que `startGame` (`{ onChange, getState, onExit }`) et `target = { blockId: 'maze', level? }`; `main.js` appelle `startMaze` quand le bloc est `maze`.
Comportement: voir « Interface » de la spec. Détails: labyrinthe en SVG (murs arrondis sombres, sol clair, étoile qui pulse doucement, héros = `getArt(id).draw()` imbriqué avec un anneau + flèche de direction); terminal (`<div role="log" aria-live="polite">` + `<input>` avec `autocapitalize="off" autocomplete="off" autocorrect="off" spellcheck="false"`, focus rendu après chaque action et au toucher du terminal); à Entrée: `parse` → erreur: ligne rouge douce + `firstkey:wrong` + son raté, sinon `execute` et rejoue les événements (déplacement ≈ 220 ms par case, rebond léger; `bump`: secousse + `wrongAnswer`; `goal`: danse + `correctAnswer`, puis chemin commun « bonne réponse »: `recordCorrect`, `handlers.onChange`, événements avec `display: '⭐'` et le `rect` du labyrinthe, relecture de `getState()`, labyrinthe suivant) pendant lequel la saisie reste possible mais est ignorée tant que l'animation du déplacement tourne (file d'attente de lignes tapées pendant l'animation: les exécuter dans l'ordre); `prefers-reduced-motion`: déplacements instantanés; `ArrowUp`/`ArrowDown` historique, `Tab` insère la suggestion s'il y en a une sinon garde son comportement natif; encadré d'aide « Nouveau: … » au premier niveau de chaque palier (texte court avec exemple dans le langage choisi) et ligne fantôme aux niveaux 1-12; aide persistante repliable avec les commandes du palier. Mise en page: grand écran labyrinthe à gauche et terminal à droite, portrait empilés; tout dans les 62 % du haut. Cleanup à la sortie (écouteurs, minuteurs, animation en cours via un jeton d'annulation). Niveau rejoué (pastille): comme `ui-game`, `fixed` suit le niveau quand on le gagne.
