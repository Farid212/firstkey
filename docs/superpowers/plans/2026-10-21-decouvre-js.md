# First Key: Découvre le JavaScript — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Un jeu sans mots où l'enfant devine les règles du JavaScript à partir d'exemples résolus et tape le résultat; 114 niveaux = 114 tours de 3 exercices, en 12 chapitres.

**Architecture:** Un script Node (`scripts/build-discover.mjs`) génère les 342 exercices avec du vrai JavaScript (évaluation à la construction uniquement) et écrit `assets/js/data/discover-js.js`; le jeu (`assets/js/ui-discover.js`) lit ces données; intégration au bloc, aux chapitres, au routage.

**Tech Stack:** JS ES modules, aucune dépendance. **Spec:** `docs/superpowers/specs/2026-10-21-decouvre-js-design.md`.

## Global Constraints
- Site statique, modules ES, pas de build côté utilisateur, aucune dépendance; `npm test` vert; l'application n'exécute **jamais** de code (pas d'`eval`/`Function` dans `assets/`); `scripts/` et `tests/` peuvent évaluer du JavaScript généré par nous.
- Aucun texte d'explication pendant l'exercice; `textContent` partout; couche `fx` inerte; contenu dans les 62 % du haut.
- Réponses: une ligne, 1 à 14 caractères, ASCII imprimable, sortie exacte de `console.log` (textes sans guillemets); sensible à la casse.
- Déterminisme: tout est figé dans le fichier de données (PRNG à graine pour la génération).
- Pas de régression sur les autres jeux, récompenses, chapitres, autocollants.

## Review Focus
1. Chaque exercice a une seule réponse correcte, vérifiée par une évaluation JavaScript réelle (tests), et ses 3 exemples **suffisent à deviner la règle** (pas de règle hors exemple, pas d'ambiguïté sur les types: `"3" + 4` etc. uniquement quand la règle est présentée par les exemples).
2. Progression: chaque tour n'utilise que des règles déjà vues dans un chapitre précédent ou son propre chapitre; difficulté non décroissante dans un chapitre; les 342 exercices sont distincts.
3. Frappe: sensibilité à la casse, toutes les réponses tapables au clavier AZERTY et QWERTY (symboles `-`, `*`, espaces, majuscules avec Maj), une touche fausse ne fait pas reculer.
4. UI: nettoyage complet en quittant, état relu après événements, barre 1/3-2/3-3/3, indice muet après 2 erreurs, mobile 360 px.
5. Anciennes sauvegardes: bloc `discover` ajouté avec progression par défaut, rien ne casse (chapitres, autocollants, badge Explorateur).

### Task 1: Générateur d'exercices et données (Node + données)
**Files:** Create `scripts/build-discover.mjs`, `assets/js/data/discover-js.js` (généré), `assets/js/discover.js`; Test `tests/discover.test.js`; Modify `package.json` (`"build:discover": "node scripts/build-discover.mjs"`).
**Interfaces — Produces:** `discover.js` (pur, sans DOM): `discoverExercise(level: number, exercise: 0|1|2): { examples: { code: string, out: string }[3], question: { code: string, out: string }, rule: string /* id de règle, jamais affiché */, hintCode?: string }`; `DISCOVER_CHAPTERS`: liste des 12 chapitres `{ id, name, short, icon, from, to }` (même forme que `chapters.js`, à y intégrer en Task 3). Les données `discover-js.js` contiennent les 342 exercices (`level` 1..114 × 3). Génération: des **familles** par chapitre (voir spec « Progression »), opérandes tirés par PRNG à graine, difficulté croissante avec le niveau du chapitre et l'exercice (petits nombres → plus grands, textes courts → plus longs, expressions simples → composées); chaque exercice = 3 exemples de la même règle + 1 question; `out` calculé avec du vrai JavaScript (`vm`/`Function` à la construction) et formaté comme `console.log` (une ligne, sans guillemets pour les textes; plusieurs `console.log` ou valeurs → une seule ligne séparée par des espaces: pour les `if`/`else` et boucles, le `code` est un petit programme de 1 à 4 lignes et `out` est la sortie concaténée sur une ligne).
- [ ] **Step 1 tests** (`tests/discover.test.js`): pour les 342 exercices: re-évaluer `code` des 3 exemples et de la question avec un vrai moteur JavaScript (`new Function` avec une console capturante, dans le test seulement) et comparer à `out`; les réponses (`question.out`) font 1 à 14 caractères ASCII imprimables, sans retour à la ligne; les 3 exemples ont des `out` différents entre eux et différents de la réponse (pas de règle triviale: au moins 2 exemples ont des sorties distinctes), `question.code` différent des exemples; les 342 exercices sont deux à deux distincts (`question.code`); pas de doublon d'exemples dans un même exercice; chaque règle (`rule`) d'un exercice apparaît dans son chapitre ou un chapitre précédent (table `RULES_BY_CHAPTER`); difficulté non décroissante dans un chapitre (mesure: longueur du code de la question + nombre d'opérations, tolérance documentée); aucun usage de `Date`/`Math.random` dans les exercices; les 12 chapitres couvrent exactement 1..114.
- [ ] **Step 2:** échec; **Step 3:** implémenter script + données + `discover.js`; **Step 4:** `npm test` vert; **Step 5: Commit** `feat: exercices « Découvre le JavaScript »`.

### Task 2: Moteur de frappe sensible à la casse et écran du jeu
**Files:** Modify `assets/js/typer.js` (option `caseSensitive`), `tests/typer.test.js`; Create `assets/js/ui-discover.js`; Modify `assets/css/style.css`.
**Interfaces — Consumes:** `discoverExercise`, `createTyper(accepts, { caseSensitive })`, `recordCorrect`, événements `firstkey:*`, `getArt`/`CREATURES`. **Produces:** `startDiscover(root, state, target, handlers)` (mêmes `handlers` que `startGame`/`startMaze`: `{ onChange, getState, onExit }`, `target = { blockId: 'discover', level? }`).
Comportement: voir la spec « Interface ». Détails: exercice = `discoverExercise(level, exercise)` avec `exercise = state.progress.discover.correct` (niveau courant) ou compteur local 0..2 pour un niveau rejoué (comme `ui-maze.js`); 3 lignes d'exemples puis la ligne à compléter avec une case vide par caractère attendu (un caractère tapé juste remplit sa case en vert; la frappe fausse = son `wrongAnswer`, secousse légère de la ligne, événement `firstkey:wrong`, la saisie ne recule pas); après 2 erreurs sur l'exercice: indice muet (surbrillance douce du `hintCode` ou de la partie de l'exemple qui contient la règle); victoire: ligne verte + saut de la créature (dernière débloquée), `correctAnswer`, voie commune (`recordCorrect`, `handlers.onChange`, `firstkey:correct` avec `display` = code de la question, `rect` de la console, `firstkey:levelup` si applicable, relecture `handlers.getState()`), exercice suivant (barre 1/3-2/3-3/3 via `answersPerLevel(age, 'discover')`); `e.repeat` ignoré; touches non imprimables ignorées (Tab/Entrée/Échap: Échap = retour); AZERTY/QWERTY: s'appuyer sur `e.key`; pas d'écouteur qui fuit (retrait en sortie), `prefers-reduced-motion`: pas d'animation. `typer.js`: `createTyper(accepts, opts = {})`, `opts.caseSensitive` (défaut faux = comportement actuel); tests typer: sensible/insensible.
- [ ] **Step 1 tests** (typer): option `caseSensitive`; le comportement par défaut est inchangé. **Step 2:** implémenter l'écran et le CSS. **Step 3:** `npm test` vert. **Step 4: vérification Chrome** après Task 3 (l'écran n'est accessible qu'une fois le bloc branché; pour tester dès maintenant, appeler `startDiscover` depuis la console ou brancher d'abord Task 3). **Step 5: Commit** `feat: écran « Découvre le JavaScript »`.
