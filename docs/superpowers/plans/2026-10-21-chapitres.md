# First Key: chapitres, chemin et autocollants — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Découper les 114 niveaux de chaque jeu en chapitres nommés; sur l'accueil, carte de jeu = bouton « Continuer » + vignettes de chapitres + chemin sinueux dépliable; fin de chapitre = autocollant.

**Architecture:** Table pure `assets/js/chapters.js`; autocollants dans le modèle `rewards` (données, moteur, directeur, collection); UI de l'accueil refaite dans `ui-home.js` (carte de jeu, vignettes, chemin SVG).

**Tech Stack:** JS ES modules, SVG, CSS, aucune dépendance. **Spec:** `docs/superpowers/specs/2026-10-21-chapitres-design.md`.

## Global Constraints
- Site statique, modules ES, pas de build, aucune dépendance; `npm test` vert; textes via `textContent`; SVG par `createElementNS`.
- Aucune perte de progression; anciennes sauvegardes chargées (backfill des autocollants sans fête).
- Un chapitre verrouillé n'est jamais cliquable; les niveaux atteints sont toujours rejouables.
- `prefers-reduced-motion` respecté; cibles tactiles ≥ 48 px; pas de défilement horizontal de la page; la couche `fx` reste inerte.
- Le comportement des jeux (questions, labyrinthes, récompenses, score) ne change pas.

## Review Focus
1. Les chapitres de chaque jeu couvrent exactement 1..114 et correspondent au contenu réel (quiz: thèmes là où les programmes apparaissent; labyrinthe: `CURRICULUM`; lettres/mots: progression réelle).
2. Un autocollant n'est donné qu'une fois, seulement au vrai passage du dernier niveau d'un chapitre (jamais par saut parent), la file d'animations garde ses garde-fous (≤ 5, ordre niveau → créature → badge → autocollant), le backfill ne fête rien.
3. Accueil: état de chaque vignette correct à tous les niveaux (1, bornes de chapitre, 114), clavier et lecteur d'écran, un seul chemin ouvert, retour de partie qui rouvre le bon chapitre, aucune fuite d'écouteur (Échap), mobile 360 px sans défilement horizontal.
4. Anciennes sauvegardes et sauvegardes corrompues (`rewards.stickers` invalide).

### Task 3: Accueil à chapitres (carte « Continuer », vignettes, chemin)
**Files:** Modify `assets/js/ui-home.js`, `assets/js/main.js`, `assets/css/style.css`, `README.md`; Test: logique pure éventuelle dans `tests/chapters.test.js` (ex. géométrie du chemin si extraite en fonction pure `pathPoints(count, width)`); le DOM se vérifie à la main.
**Interfaces — Consumes:** `CHAPTERS`, `chapterState`, `chapterProgress`, `chapterColor`, `stickerSvg`, `state.rewards.stickers`, `levelSpec` n'est pas nécessaire (progress.maze.correct suffit pour les points du labyrinthe).
Comportement: voir la spec « Objectifs » 2, 3, 5 et « Interface (détails) ». `gameCard(b, state, handlers)` devient: en-tête (icône, nom), bouton **▶ Continuer · <chapitre> · niveau N** (+ « · en Python » pour le labyrinthe), rangée de vignettes (`role="list"`, chaque vignette `<button>`; verrouillées `disabled`), panneau de chemin déplié (`aria-expanded` sur la vignette, `id` du panneau, focus géré). Le chemin: étapes = niveaux du chapitre, positions en courbe sinueuse (fonction pure `pathPoints`), étape faite verte (clic = `onPickLevel(blockId, level)`), en cours orange qui pulse (désactivé avec reduced-motion) avec le portrait de la créature (`getArt(CREATURES[unlocked-1].id).draw()`), futures grisées `disabled`, dernier emplacement = autocollant (`stickerSvg`, grisé si pas gagné), bouton « ▶ Jouer le niveau N ». Labyrinthe: 3 points (exercices faits d'après `progress.maze.correct` pour le niveau courant, tous pleins pour un niveau passé, vides pour un futur); autres jeux: anneau (`correct / answersPerLevel(age)`). Un seul chemin ouvert par carte (par défaut celui du chapitre courant); `renderHome` reçoit le jeu quitté (`focusBlock`) et rouvre son chapitre courant. Échap replie (écouteur nettoyé quand l'accueil est quitté). Cibles ≥ 48 px, aucune grille de 114 pastilles. `main.js`: transmet `onPlay`/`onPickLevel`/`focusBlock` comme aujourd'hui.
